CONCEPTO 01

¿Qué hace que una red sea SDN?

En una red definida por software se separa el plano de control del plano de datos. El Controller toma decisiones de encaminamiento; los routers o dispositivos de reenvío aplican esas decisiones.

ControllerDecide la ruta
→
RouterReenvía el paquete
→
DestinoRecibe los datos
CONCEPTO 02

Las métricas de los enlaces

Retardo (ms)

Tiempo que tarda un paquete en atravesar un enlace. Se suman los retardos del camino.

Ancho de banda (Mbps)

Capacidad del enlace. El ejemplo usa el costo aditivo 1/ancho_de_banda; no equivale al cuello de botella extremo a extremo.

Pérdida (0–1)

Probabilidad de pérdida por enlace. El costo usado es −ln(1−p), que permite sumar pérdidas en el camino.

CONCEPTO 03

¿Por qué cambia una ruta?

El Controller calcula el camino de menor costo con Dijkstra. Si un enlace falla, deja de estar disponible y el cálculo se repite sobre los enlaces activos.

Prueba T1: A → B → D tiene 20 ms. Si falla B–D, el camino alternativo A → C → D tiene 35 ms.
CONCEPTO 04

Construye tu propia red

Importa un JSON con nodos y enlaces. Cada nodo puede tener ciudad, latitud y longitud. Si no defines coordenadas, el mapa asigna posiciones ilustrativas para poder explorar la topología.

{ "nodes": [{"id":"R1","city":"Bogotá","lat":4.71,"lon":-74.07}], "links": [{"node_a":"R1","node_b":"R2","delay_ms":5,"bandwidth_mbps":100,"loss_probability":0.01}] }

EMPIEZA AQUÍ

Tu primer experimento SDN

  1. Usa Cargar T1 de ejemplo o importa tu topología JSON.
  2. Pulsa Seleccionar emisor y haz clic en un router; luego pulsa Seleccionar destinatario y haz clic en otro. Si no activas un campo, el router solo se inspecciona.
  3. Elige una métrica y pulsa Simular envío.
  4. Haz clic en los enlaces para revisar sus métricas; puedes interrumpir uno y volver a simular.
  5. Abre Aprender SDN para entender los conceptos detrás del resultado.
